# Задание 0. Каркас проекта

**Цель.** Пустой, но настоящий проект, в котором дальше будут жить
библиотеки: сборка через пресеты, тесты и политика предупреждений, которая не
протекает к тем, кто встроит проект к себе.

Шаги идут так, чтобы после каждого проект собирался и ошибка была видна
сразу.

## Шаг 1. Репозиторий

`git init` и `.gitignore` с `/build/` и `/.cache/`. Конфиги можно
скопировать из cannet, это не код:

- `.clang-format` — как есть;
- `.clangd` — только блок `Diagnostics`;
- `.vscode/settings.json` — если работаешь в VS Code.

## Шаг 2. Минимальный CMake

`CMakeLists.txt` с `project(canux …)` и библиотека-заглушка с одной функцией
на C++23. Собрать вручную, без пресетов:
`cmake -S . -B build/tmp -G Ninja && cmake --build build/tmp`.

## Шаг 3. Пресеты

`CMakePresets.json` с пресетами `debug`, `release` и `debug-asan` для
configure, build и test. Генератор Ninja, деревья сборки в
`build/<preset>`, плюс `compile_commands.json`. Удалить `build/tmp` и
проверить: `cmake --preset debug && cmake --build --preset debug`.

## Шаг 4. Standalone и опции

`CANUX_STANDALONE` показывает, собирается ли проект сам или его встроили
через `add_subdirectory`. Опции:

- `CANUX_WERROR` и `CANUX_BUILD_TESTS` — по умолчанию равны standalone;
- `CANUX_SANITIZE` — по умолчанию OFF.

## Шаг 5. Политика сборки

INTERFACE-таргет `canux_build_config`, в нём:

- предупреждения из `~/dev/cannet/CLAUDE.md` и всё, что сам считаешь
  полезным;
- `-Werror` по опции;
- `-fstack-protector-strong`, `_GLIBCXX_ASSERTIONS` в Debug,
  `_FORTIFY_SOURCE=3` в оптимизированных сборках;
- ASan+UBSan по опции.

Подключить его к заглушке как PRIVATE. Здесь же — эксперимент 1 из шага 7.
Standalone-сборка без пресета и без `CMAKE_BUILD_TYPE` — командой из шага 2 —
тоже должна проходить.

## Шаг 6. Тесты

Catch2 v3: системный, а если его нет — закреплённая версия через
FetchContent. В системе стоит Catch2 3.13 (`catch-devel`), так что фолбэк
надо проверить отдельно: configure в отдельную папку, где `find_package` его
не находит, скачивает закреплённую версию, и тесты проходят; нужна сеть.
Тест к заглушке; каждый `TEST_CASE` — отдельная
запись в CTest. `ctest --preset debug` проходит, и то же для `release` и
`debug-asan`.

## Шаг 7. Эксперименты

Результат каждого описать одной строкой, изменения потом откатить.

1. Неявное сужение `int` → `std::uint8_t` в заглушке валит
   standalone-сборку.
2. Маленький проект-потребитель во временной папке подключает canux через
   `add_subdirectory`:
   - он собирается без `-Werror`, без тестов canux и не скачивает Catch2;
   - такое же сужение в его собственном `main.cpp` проходит без
     предупреждения (флаги смотреть в его `compile_commands.json`).
3. Выход за границу `std::vector` через `operator[]` с индексом, которого
   компилятор не знает заранее: в Debug программа падает с сообщением
   libstdc++, в Release молчит.
4. В `debug-asan` ASan ловит выход за границу кучи через сырой указатель, а
   UBSan — переполнение `int`. Падает ли при этом тест? Если нет — сделать
   так, чтобы падал.

## Шаг 8. Вопросы

На каждый — пара предложений.

1. Почему политика сделана INTERFACE-таргетом, подключённым как PRIVATE, а
   не через `add_compile_options` или `CMAKE_CXX_FLAGS`? Что сломается при
   PUBLIC? Какое требование это накладывает на публичные заголовки?
2. Почему `-Werror` включён только в standalone-сборке?
3. Почему `_FORTIFY_SOURCE` не работает без оптимизации и чем уровень 3
   лучше уровня 2?
4. Какие из твоих предупреждений имеют смысл только для C++ и зачем
   оборачивать их в `$<COMPILE_LANGUAGE:CXX>`?
5. Что даёт `SYSTEM` в `FetchContent_Declare` и зачем закреплять версию?
6. gnu++23 или c++23: что выберешь, почему и как задать это в CMake?
   Подсказка: сравни вывод `g++ -std=gnu++23 -dM -E -x c++ /dev/null` с тем
   же для `-std=c++23`.
